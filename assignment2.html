Method · Concept Definition

两个过程，一条从概念到需求的链

概念定义阶段只做两件事：定义问题与方案类；定义相关方需要与需求

按第 4 章框架，本阶段由业务或使命分析与相关方需要与需求定义两个过程组成。前者站在业务管理层面回答“要不要做、做哪一类”，后者站在业务运行层面回答“为谁做、做成什么样”。

PROCESS / 01

业务或使命分析

输入组织战略与现有 ConOps，输出问题/机会空间、首选解决方案类、初步生存周期概念与 BRS。核心动作是对标现状与未来、识别差距。

PROCESS / 02

相关方需要与需求定义

识别相关方 → 获取需要 → 分析并转化为需求 → 确认协商 → 建立追溯，输出 StRS 与 OpsCon。

KEY / NEED ≠ REQ

需要是期望，需求是共识

需要只代表某一方立场，常带预设方案、残缺且互相冲突；需求必须综合各方、补齐隐含信息、加约束并做到单一可验证。

Business / Mission Analysis

GAP / 01–02

人进不去，装备也进不去

G1 城镇废墟、坑道、雷场中人员进入即暴露，伤亡风险随城区作战比例上升；G2 轮式越不了台阶、履带跟不上节奏、足式跑不远——结构性矛盾。

Concept of Operations · Organization Level

ConOps：部队打算怎么用这组系统打仗

多系统、多对多的全局画面；本平台只是其中一个黑盒

ConOps 描述组织层面的运行意图：在什么任务、用什么编成、按什么流程、受什么约束。它不是用户愿望清单，必须由相关方共同开发并保证工程可行。

MISSION

任务想定

某合成旅在城镇—山地混合地形执行“清剿夺控”。敌依托建筑、废墟与坑道设防，以狙击、IED、小型无人机侦察袭扰。

THREAT

对抗条件

敌具备电子干扰与 GNSS 压制能力；城区 GNSS 部分可用；建筑遮挡导致链路不稳，需中继保障。

CONSTRAINT

关键约束

附带损伤限制、明确 ROE、开火须人在回路授权、不得越出授权地理围栏。

业务需求规格说明（BRS）

按教材表4-1 的 8 章轮廓输出；点击章节展开正文

BRS 站在业务管理层面，回答组织为什么要改变业务、如何利用系统促进业务。为便于评审，8 章默认折叠，标题右侧为章节摘要。

1

简介

目的 · 范围 · 概况 · 定义 · 主要相关方▸

业务目的：作战样式向分布式、无人化演进，城镇与山地高危地形中的侦察、清除与伴随支援任务对人员暴露的容忍度持续下降。现役地面装备存在“轮式进不去、履带跟不上、足式跑不远”的结构性矛盾，地面末端缺少可进入、可持续的智能节点。

本项目的业务目的是研制轮腿式无人作战平台，以轮-腿复合构型兼顾道路机动效率与复杂地形通过性，作为地面末端智能节点接入现有作战体系，使作战单元在人员零暴露或低暴露条件下获得持续的战术态势、精确打击与危险处置能力。

  • 业务域：陆军合成部队地面无人作战（Ground Unmanned Combat Operations）。
  • 范围内活动：任务筹划与目标分配、前沿侦察与目标指示、建筑物与废墟搜索清除、IED/未爆物处置、伴随支援与物资前送、打击效果评估、训练与保障。
  • 系统范围：1 套平台（整机、载荷接口、控制终端、保障与检测设备、备附件）；不含指挥信息系统、弹药与武器本体、空中平台。
  • 业务三层：作战指挥层（任务与授权）— 无人分队运用层（操控与协同）— 平台与保障层（整机、载荷、维修补给）。
主要相关方：军方采办（SH-05）、作战部队（SH-03）、总体研制（SH-01）、试验鉴定（SH-04）、配套供应商（SH-02）为高影响力；标准法规（SH-13）与军控智库（SH-14）通过规则约束业务边界。完整清单见 §04。

业务管理需求

环境 · 使命目标 · 业务模型 · 信息环境▸
  • 业务环境：城市作战比例上升、战场向建筑密集与地下空间延伸；对手电子战与小型无人机能力提升，GNSS 与链路可靠性下降；无人系统伦理法规趋严。内部：编制与训练体系在建、维修保障能力有限、经费与批产规模受限。
  • 使命：为合成部队提供可进入高危地形的地面无人作战能力。目的：降低人员伤亡、压缩杀伤链、扩展感知与机动边界。
  • 目标（SMART）：3 年内完成样机与定型试验；形成连排级运用能力；任务完成率 ≥85%；人员暴露时间下降 ≥70%；全寿命成本较履带式同类降低 ≥20%。
  • 业务模型：“军方需求牵引 + 竞争性研制 + 定型批产 + 部队运用”：军方提出需求与指标，主承包商负责总体集成，供应商提供轮腿机构、伺服、感知、计算、通信与载荷，院校提供基础技术支撑，部队反馈形成迭代闭环。
  • 信息环境：与现有地面/空中无人系统共用数据链体制与地面控制站；开放式架构与统一载荷接口纳入无人系统族谱；任务数据、地图基准、目标库集中管理并满足保密要求。
4

业务运行需求

过程 BP · 策略规则 · 约束 · 质量 · 结构▸

业务过程：BP-01 任务筹划 → BP-02 编组与配置 → BP-03 机动投送 → BP-04 前沿侦察 → BP-05 目标处置 → BP-06 撤收归档 → BP-07 保障循环。

  • 策略与规则：开火须人在回路授权，平台不得自主决定杀伤；有人平台对无人平台保持指挥关系，紧急情况可一键接管或迫停；城区遵守附带损伤限制与 ROE，活动受地理围栏约束；通信静默与频谱使用服从战场电磁频谱管理。
  • 约束：不得造成不可接受的附带损伤，武器需具备精确打击/最小当量能力；侦察阶段控制噪声与红外特征；不得越出授权区域，越界须自动告警并停止前进。
  • 运行质量：任务成功率 ≥85%；态势回传端到端时延 ≤2 s；平台可用度 ≥90%；识别虚警率 ≤10%；单次任务战损率 ≤10%；出动准备 ≤15 min。
  • 业务结构：指挥“旅—营—无人作战分队”三级；保障“营保障排—旅修理所—工业部门”三级维修。
5

提案系统初步运行概念

六项能力 · 五种模式 · 五个场景▸

初步运行概念：轮-腿复合构型地面无人平台，具备复合机动、多模态感知、自主决策、任务载荷、协同通信、能源保障六项核心能力；运行模式分遥控、监督自主、协同编组、失效降级、储运维护五种；用户类型为操作员、指挥员、维修人员与保障人员；支持环境为城镇、山地、坑道，-30～+55 ℃，IP67。

  • SC-01 城镇建筑物搜索清除：轮行接近街区 → 腿行上楼梯与废墟 → 室内搜索 → 目标指示 → 授权打击。
  • SC-02 山地坑道侦察：长距离轮行 → 坑道口切腿行 → 低光/无光建图侦察 → 数据回传。
  • SC-03 伴随突击：与步战车协同推进，前出侦察并提供目标指示。
  • SC-04 物资前送：载荷换装物资箱，按预设路线前送至前沿班组。
  • SC-05 失联自主返航：链路中断后自主判定、返航或待机、重连恢复。

其他初步生存周期概念

采办 · 部署 · 支持 · 弃置▸
  • 采办：竞争性研制 + 样机竞标 + 定型试验 + 批量采购。
  • 部署：车载投送为主、两人可短距搬运；展开 ≤5 min。
  • 支持：三级维修、模块化换件、备件与电池集中管理、软件远程升级。
  • 弃置：电池梯次利用与合规回收、弹药与危险品销毁、存储数据彻底擦除。

相关方需求规格说明（StRS）

按教材表4-5 的 8 章轮廓输出；与 BRS 的差别在抽象层次

BRS 说“业务要什么成效”，StRS 说“系统在什么场景下必须做到什么”。两者章节名称高度相似，这是评审时最容易被追问的点。

1

简介

相关方目的 · 范围 · 概况 · 定义 · 相关方▸

相关方目的：获得“进得去、看得见、打得着、回得来”的地面无人作战能力——分队希望以更少暴露完成城区与坑道侦察清除；指挥员希望获得可用实时态势与可控打击手段；保障人员希望好修、好换、好搬；采办与鉴定方希望指标可测、风险可控。

  • 范围：使用（合成旅/营无人分队、配属侦察火力单元）· 保障（营保障排、旅修理所、后方仓储）· 训练（院校与训练基地）· 采办鉴定（军代局、试验鉴定机构）· 研制（主承包商、分系统供应商、科研院所）。
  • 概况：系统在体系中处于地面末端：向上接受指挥所任务与授权，横向与有人战车、无人机交换态势，向下与保障分队发生物质与能量交互。边界含整机、载荷接口、控制终端；边界外为链路、指挥系统与弹药。
  • 定义补充：自主等级按 AL-1（辅助）至 AL-5（完全自主）划分，本系统目标为 AL-3 有条件自主（关键决策人在回路）；接管指操作员从自主切回直接控制，须有明确状态反馈。
  • 相关方：18 类（SH-01～18），分直接、交互、施加影响/被影响三类，详见 §04。

业务管理需求

环境三特征 · 使命目标 · 运行模式 · 信息环境▸

环境三特征：城区与地下空间通信遮挡严重、GNSS 可用性不稳定；对手具备电子干扰与低成本无人机侦察能力；交战距离近、时间窗口短，决策必须前压。三者共同决定系统不能依赖单一导航与单一链路。

  • 使命/目的/目标：以无人替代有人进入高危区域 → 降低伤亡、缩短反应时间、扩大可控区域 → 单次任务完成率 ≥85%、人员暴露下降 ≥70%、发现到打击 ≤60 s。
  • 业务模型：“分队编配、集中训练、分级维修、按任务循环使用”：每分队编配 3～6 台，任务间隙在保障点换电检测，故障按模块级更换、离位送修。
  • 信息环境：接入指挥信息系统与情报体系，共享地图基准、目标清单与态势；对外接口采用统一消息格式、支持标准数据链；对外数据加密并满足涉密管理要求。
4

系统运行需求

过程 SP · 策略 · 约束 · 模式与状态▸

系统过程：SP-01 自检入网 → SP-02 机动（轮行/腿行/复合）→ SP-03 感知（建图定位识别跟踪）→ SP-04 决策（路径、分配、规避、交战建议）→ SP-05 载荷作业 → SP-06 协同 → SP-07 失效处置 → SP-08 保障。

  • 策略与规则：自主等级 AL-3，授权任务内自主规划行驶，开火须人确认；权限优先级“人工接管 > 预置任务 > 自主优化”，接管 ≤1 s 生效并反馈；失效安全优先于任务完成；失联 60 s 判失联，按预置策略返航或待机，重连后先同步状态再恢复任务。
  • 约束：-30～+55 ℃，IP67，抗雨雪沙尘，抗 0.5 m 跌落；满足军用 EMC 且不干扰同编队通信导航；可车载固定、两人短距搬运；侦察工况噪声 ≤65 dB @30 m。
  • 模式与状态：M1 遥控 / M2 监督自主 / M3 协同编组 / M4 失效降级 / M5 储运维护。任何迁移须在终端显示当前模式与切换原因；M1↔M2 为常态，M4 只能由系统自动进入、人工确认退出。

详细生存周期概念

运行 · 场景 · 采办 · 部署 · 支持 · 弃置▸
  • 运行概念：按 S0～S7 八个阶段循环，常态 M2，进建筑与坑道降级 M1，多平台编组 M3，异常 M4（见 §03）。
  • 运行场景：SC-01～SC-05 见 BRS §5；补充 SC-06 夜间街区巡逻警戒、SC-07 灾后/事故现场侦察（非战争运用）。
  • 采办：两阶段竞争，方案阶段 2 家并行研制样机，比测后择优定型，分批采购并由部队试用收集数据。
  • 部署：编制到无人作战分队，3～6 台/分队；步战车或运输车投送；展开与撤收各 ≤5 min；具备伴随保障与前出保障两种形态。
  • 支持：三级维修（分队换件换电 / 旅级模块更换检测 / 工业部门部件修理大修）；备件“易损件前置、贵重件集中”；软件远程升级与版本管理。
  • 弃置：电池危险品回收或梯次利用；武器弹药接口件按军械规程销毁；存储介质彻底擦除；金属与电子件循环利用。
